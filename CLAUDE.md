# DelfosT hub

The personal hub of **DelfosT**: one static site that says who DelfosT is and links to everything
they make. Visitors are a mix of readers, other creators and recruiters who may give it under a
minute, so everything must be reachable from the first screen in one or two clicks.

## The rule that outranks every other

DelfosT is a pseudonym and the only name that may ever appear. Never write, ask for, or infer the
owner's real name, employers, schools, city, country, personal email, phone or personal social
handles: not in content, code, comments, metadata, file names, commit messages or commit identity.
The one exception is the GitHub account that hosts the code, which the owner has chosen to publish.

- Experience is deliberately brief and anonymous ("a language-learning company", "a university
  extension course"). Do not make it more specific, even if the owner's CV is shared in a session.
  The CV itself must never be copied into this repository.
- The GitHub account that hosts the code is public: `github.owner` in `site.config.mjs` builds the
  "Source" links from it and the repository names in content (`repo:` in `projects.yaml` and
  `minis.yaml`). Only the account is public. It does not make anything else about the owner
  public, and a private term that sits inside the account's name is still found elsewhere (the
  check ignores the account's own name, nothing more). Clearing `github.owner` builds a site with
  no link to a code-hosting site, and `pnpm check` fails if one appears without it.
- `pnpm check` and the pre-commit hook scan for a private list of terms kept **outside** the repo
  at `~/.config/delfost-hub/private-terms.txt`. Never copy that file or its contents in here, and
  never print a matched term: reports name terms by position only.
- Commits use the identity `DelfosT <delfost@noreply.invalid>`, set in this clone's git config.
  Check `git config user.name` before the first commit in a new clone.

## Commands

Use pnpm through Corepack (`corepack pnpm …`); the version is pinned in `package.json`.

| Command | What it does |
| --- | --- |
| `pnpm dev` | Local site with live reload. The security policy is not applied in dev. |
| `pnpm build` | Sync posts, build to `dist/`, write the final headers file. |
| `pnpm preview` | Serve `dist/` (starts in the background; `pnpm astro preview stop` ends it). |
| `pnpm check` | Type check, build, then the safety checks. Run before publishing. |
| `pnpm sync` | Refresh `content/writing.synced.json` from the project sites (`--full` refetches all). |
| `pnpm images` | Regenerate `og.png` and the PNG icons. Needs a Chromium-family browser. |

## Where things live

```
content/             Everything a visitor reads. Edit here, not in src/.
  projects.yaml        main projects (own sites): colour, glyph, facts, optional feed
  minis.yaml           mini projects
  writing.yaml         hand-added posts, and overrides for synced ones
  writing.synced.json  generated by `pnpm sync`; do not edit
  experience.yaml      path, focus, skills, languages
  about/en.md, es.md   the About text and the contact line
site.config.mjs      Site-wide switches: public URL, writing limit, GitHub account for the source
                     links, analytics
src/
  content.config.ts    schemas: a wrong or missing field fails the build with a clear message
                       (`repo` is a repository name only; `preview` captions a project's picture)
  i18n/ui.ts           interface words in both languages, and the list of sections
  components/          one file per section; Home.astro composes the page
  layouts/Base.astro   <head>, metadata, and the only script on the site
  styles/global.css    the design system: colours, type, shared shapes
  assets/fonts/        the four font files, self-hosted
  assets/previews/     one 1280 x 640 picture per main project (optional), named after its id
public/_headers      security headers (hand-written part)
scripts/             sync-writing, write-headers, check, make-images
```

Pages: `/` (English), `/es/` (Spanish), `/404.html`. Both home pages render `Home.astro`.

## Conventions

**Content, not code.** Adding a project, post, mini project or experience entry is an edit to a
file in `content/`. If a request seems to need a code change for that, the schema is probably
missing a field: extend the schema rather than hard-coding.

**Two languages, always.** English is the default, Spanish the second. Every visible string has
`en` and `es`; the schema rejects a missing one. Post titles stay in their original language and
carry a language tag. Write Spanish in a neutral register and avoid regionalisms.

**The visual direction** is a game command menu under a painted sky: Persona-style interface
(condensed slanted type, cut slabs that snap behind whatever is selected, hard offset shadows) in
a fantasy concept-art setting (night scene, moon, a crossroads signpost with one arm per project).
The day theme is the same scene at dawn. Clarity wins over decoration: if an ornament competes
with text, remove the ornament. The owner asked for calm, nothing flashy or esoteric: no
particles, meters, rails, sigils or invented lore. An addition earns its place by being useful
(a picture of the project's site, a mark for the section being read), not by being decorative.

- Colours come only from the tokens at the top of `global.css`. Dark is the default theme.
- A project's colour is only ever a fill with `--ink` text on top, never a text colour. The
  schema enforces a contrast of 4.5:1 against the ink.
- Two type families only: Barlow Condensed (display, labels) and Alegreya (reading text).
- The "slab" (a `--slab` block with a slanted edge) is the one hover and focus language for rows,
  links and tiles. Reuse it instead of inventing a new effect.
- Every interactive element needs a visible focus state, a 44px touch target, and must work with
  the keyboard. Motion sits inside `prefers-reduced-motion: no-preference` or is neutralised by
  the global reduce rule.

**The security policy shapes the markup.** Every page ships a Content Security Policy that allows
nothing by default.

- No `style="…"` attributes and no inline event handlers. `pnpm check` fails on both.
- A colour that comes from content is drawn as an SVG `fill` attribute, which the policy allows
  (see the project cards and the signpost). Do not use `define:vars`.
- Scripts and styles written in `.astro` files are hashed automatically. The one hand-inlined
  script is `src/lib/theme-script.mjs`, whose hash is computed in `astro.config.mjs`.
- Nothing loads from another origin. A new third-party resource needs a deliberate change to
  `security.csp` in `astro.config.mjs`, and a reason.
- `animation-timeline` must stay in a separate rule from the `animation` shorthand (see
  `Header.astro`): the CSS minifier merges them into something browsers reject.

**Small and fast.** The page is HTML with its CSS inline, four font files and one small script.
Budgets checked by `pnpm check`: home page under 30 kB compressed, scripts under 15 kB. No UI
framework and no client-side rendering. Add a dependency only when it removes more code than it
brings, and say so.

**Analytics hooks.** Links and buttons carry `data-track="<kind>:<id>"` (`project:hibi`,
`post:/path/`, `mini:<id>`, `repo:<id>`, `nav:<section>`, `menu-hero:<section>`, `lang:es`,
`theme`). Keep the attribute on anything new that can be clicked. Nothing is sent until Umami is
switched on (see Status); its event names are cut to 50 characters.

**Motion and keys.** Anything that moves sits inside `prefers-reduced-motion: no-preference` or is
neutralised by the global reduce rule. The menus move with the arrow keys, but only while focus is
inside them, so no single-key shortcut is active on the page at large. The only scroll-driven
script besides the theme is the mark in the bar for the section being read.

**Pictures of the projects.** A main project may carry a `preview` (a 1280 x 640 capture of its home
page, `src/assets/previews/<id>.webp`, with `alt` text in both languages). Capture it from the live
site, **look at it** before committing (nothing personal may be in the frame, and strip metadata),
and expect to refresh it when the site changes. Astro resizes it at build time; it loads lazily.

## Verifying a change

1. `pnpm check` passes.
2. Look at it: `/` and `/es/`, dark and light, a phone width (390px) and a desktop width, and tab
   through anything interactive. Text that fits in English often wraps in Spanish.
3. For anything touching scripts, styles or headers, test the **built** site (`pnpm build` then
   `pnpm preview`), because the security policy is not active in `pnpm dev`.

## Status

Built, verified and live at https://hub.delfost.workers.dev: the full page in both languages and
themes, the post sync, the safety checks, the social image and icons.

**Hosting.** A Cloudflare Worker named `hub` serves `dist/` as static assets (`wrangler.jsonc`):
`dist/_headers` carries the headers and unknown addresses get the 404 page. A Workers Builds
trigger watches this repository's `main` branch: every push runs `pnpm run build`, then
`npx wrangler deploy`. Two consequences:

- The build runs on Cloudflare, where the private terms list does not exist, so `pnpm check`
  (run locally before pushing) is the gate, not part of the build.
- `pnpm sync` runs inside that build, so new posts from the project sites reach the hub on its
  next build, that is, on the next push. Publishing on a project site alone does not refresh it.

By hand, `pnpm build` then `pnpm dlx wrangler@4 deploy` does the same thing.

**GitHub.** The repository is public and its history is a single line under the `DelfosT`
identity, written after the first history was deleted.

**Deliberately not done yet** (the owner asked to hold these for a later session):

- **Analytics.** Umami Cloud, the service the first hub used: cookie-free page views, and a click
  event for everything marked `data-track`. It is built and dormant: paste the website ID from the
  Umami dashboard into `analytics.umami.websiteId` in `site.config.mjs` to switch it on (the first
  hub's ID was not kept anywhere on the machine). Switching it on adds the tracker, allows exactly
  its two hosts in the security policy and changes the footer note; the tracker honours Do Not
  Track. Nothing is collected before that.
- **Contact.** The owner chose to show no contact details for now. `content/about/*.md` accepts a
  `contactUrl` when that changes.
